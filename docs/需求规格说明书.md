## 1. 产品概述

### 1.1 产品定位

AI小说转剧本工具是一款面向影视编剧、内容创作者、网文作者的 SaaS 工具。用户上传小说文本文件，选择目标剧本类型，系统自动调用大语言模型（LLM）将小说内容转换为结构化的专业剧本格式（YAML），并提供在线编辑、预览与导出能力。

### 1.2 目标用户

| 用户角色 | 典型场景 | 核心诉求 |
|---------|---------|---------|
| 影视编剧 | 将签约小说改编为电影/电视剧剧本初稿 | 快速生成符合行业格式的剧本骨架，节省逐章手写时间 |
| 网文作者 | 将自己作品转换为微短剧剧本，寻求IP变现 | 一键生成竖屏微短剧格式，快速验证改编可行性 |
| 制片人/项目策划 | 评估小说IP的影视化潜力 | 快速预览小说改编后的剧本结构与节奏 |

### 1.3 产品边界

- **包含**：小说文本上传 → 章节解析 → AI剧本转换 → 在线编辑 → 导出YAML → 历史项目管理
- **不包含**：PDF/Word/EPUB等非纯文本格式的小说解析（v1.0阶段）、多人协作编辑、剧本语言润色人工服务、OCR纸质书识别

## 2. 功能性需求

### 2.1 用户认证与账户管理

#### FR-01 用户注册

| 字段 | 说明 |
|------|------|
| 优先级 | P0（必须） |
| 描述 | 用户通过邮箱+密码注册账号，密码≥8位且含字母+数字 |
| 输入 | 邮箱、密码、确认密码 |
| 输出 | 注册成功→跳转登录页；注册失败→提示具体错误原因 |
| 异常 | 邮箱已注册→提示"该邮箱已被注册，请直接登录"；密码强度不足→提示规则 |

#### FR-02 用户登录

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 邮箱+密码登录，采用JWT Token认证，有效期24小时 |
| 异常 | 密码错误连续5次→账户锁定15分钟；未登录访问受保护页面→重定向登录页 |

#### FR-03 用户登出

| 字段 | 说明 |
|------|------|
| 优先级 | P1 |
| 描述 | 主动登出时Token加入Redis黑名单，立即失效 |

### 2.2 小说上传与章节解析

#### FR-04 小说文件上传

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 用户上传小说文件，系统校验后存储 |
| 支持格式 | `.txt`、`.md`（UTF-8编码） |
| 文件限制 | 单文件≥3章，单文件上限 50 万字（UTF-8 编码下文件大小约 1.5 MB），若超过则提示"文件过大，当前支持最大50万字" |
| 上传方式 | 点击上传区域选择文件，或拖拽文件至上传区域 |
| 异常 | 非支持格式→提示"仅支持 .txt / .md 格式"；文件<3章→提示"小说至少需要包含3个章节"；文件损坏/乱码→提示"文件编码异常，请使用UTF-8编码" |

#### FR-05 章节自动解析

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 上传完成后自动解析章节边界 |
| 识别规则 | 正则匹配：`第[X]章`、`第[X]节`、`Chapter X`、`第X卷`、`卷一`等常见模式 |
| 输出 | 章节列表（序号+标题+字数），展示在页面上供用户确认 |

#### FR-06 章节手动调整

| 字段 | 说明 |
|------|------|
| 优先级 | P1 |
| 描述 | 若自动解析有误，用户可手动调整章节划分 |
| 操作 | 合并相邻章节、拆分单章为多章、重命名章节标题 |

### 2.3 剧本类型选择与转换配置

#### FR-07 剧本类型选择

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 用户选择目标剧本类型，系统根据类型调整转换策略 |

| 类型 | 输出结构 | 额外配置项 |
|------|---------|-----------|
| **电影剧本** | 单文件，三幕结构 | 无 |
| **电视剧剧本** | 多集，每集独立分场 | **必填**：指定集数（范围：10-60集） |
| **微短剧剧本** | 多集，竖屏标记，每集1-3分钟 | 系统自动按章节字数估算集数 |

#### FR-08 微短剧竖屏标记

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 微短剧模式下，剧本自动标注竖屏适配信息 |
| 标记内容 | 每场`duration_seconds`（精确到秒）、每集`hook`（悬念钩子） |
| 时长规则 | 单集1-3分钟，对应5-8场；台词精简，单句对白不超过15字 |

### 2.4 AI转换引擎

#### FR-09 一键启动转换

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 用户确认章节划分和剧本类型后，点击"开始转换"，系统创建异步任务 |
| 前置条件 | 章节已解析、剧本类型已选择、电视剧模式已指定集数 |
| 触发 | 按钮点击，单次点击有效（防重复提交） |

#### FR-10 转换进度实时展示

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 通过WebSocket实时推送转换进度 |
| 进度信息 | ① 当前章节/总章节（如"第3章/共12章"）；② 百分比进度条；③ 当前状态文本（"AI正在分析第3章的角色对话..."） |
| 进度粒度 | 10% - 文件上传确认；20% - 章节解析完成；30%-90% - 各章转换中（按章节数均分）；95% - 结果合并；100% - 完成 |
| 异常 | 某章转换失败→标记该章为"失败"，其他章继续；整体失败→展示失败原因与重试按钮 |

#### FR-11 转换失败处理

| 字段 | 说明 |
|------|------|
| 优先级 | P1 |
| 描述 | 转换过程中出现异常时的处理策略 |
| 策略 | ① 单章失败：自动重试1次，仍失败则跳过并标记，完成后提示用户哪几章失败；② 全部失败：展示错误摘要，提供"重新转换"按钮；③ API超时：指数退避重试，最多3次 |

### 2.5 剧本预览与在线编辑

#### FR-12 剧本结构化预览

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 转换完成后，以卡片式布局展示剧本，按幕/集/场层级折叠 |
| 展示内容 | 场景卡片：场景标题、地点、出场人物；动作描述（斜体灰底）；对白（角色名加粗+台词） |
| 交互 | 支持展开/折叠各层级；点击场景卡片可进入编辑模式 |

#### FR-13 逐场编辑

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 点击任意场景进入编辑模式，可修改三类内容 |
| 可编辑字段 | ① 对白（`dialogue.text`）— 自由文本输入；② 动作描述（`action.text`）— 自由文本输入；③ 场景信息（`location`、`characters_present`）— 自由文本+下拉选择 |

#### FR-14 添加/删除场景

| 字段 | 说明 |
|------|------|
| 优先级 | P1 |
| 描述 | 用户可在任意位置插入新场景或删除现有场景 |
| 插入 | 在当前幕/集末尾添加，或指定位置插入 |
| 删除 | 确认弹窗："确定要删除此场景吗？此操作不可撤销" |

#### FR-15 剧本Schema合规性校验

| 字段 | 说明 |
|------|------|
| 优先级 | P0 |
| 描述 | 用户保存编辑时，前端自动校验YAML结构是否符合Schema |
| 校验时机 | 点击"保存"按钮时触发 |
| 校验规则 | ① 必要字段完整性（`meta.script_type`、`characters[].id`等）；② `script_type`枚举值合法；③ 角色引用完整（`dialogue.character`必须存在于`characters`列表）；④ 微短剧模式`hook`和`duration_seconds`不为空 |
| 校验失败 | 阻止保存，高亮显示不合规字段，展示具体错误信息（如"第3场：角色'char_005'未在角色列表中定义"） |
| 校验通过 | 保存至数据库，生成新版本号 |

## 3. 非功能性需求

### 3.1 性能要求

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| 单章转换耗时 | < 30秒 | 10章样本，取P95值 |
| 并发转换任务数 | ≥ 5个 | 压测工具模拟5用户同时触发转换 |
| 前端页面响应时间 | < 2秒（首屏加载） | Lighthouse / WebPageTest |
| 剧本编辑保存响应 | < 1秒 | 前端计时 |
| 文件上传速度 | 50万字文件上传< 3秒（在典型宽带环境下） | 百兆宽带环境 |
| WebSocket进度延迟 | < 2秒 | 后端状态变更到前端展示的时间差 |

### 3.2 可用性要求

| 指标 | 目标值 |
|------|--------|
| 系统可用率 | ≥ 99.5%（月度） |
| 计划内维护窗口 | 每周日凌晨 2:00-4:00 |
| 最大容忍宕机时长 | 单次< 30分钟 |

### 3.3 数据可靠性

| 指标 | 目标值 |
|------|--------|
| 数据持久化 | 用户剧本数据永久保存（除非用户主动删除） |
| YAML Schema合规率 | 保存时100%校验通过才能入库 |
| 数据备份 | PostgreSQL每日增量备份，每周全量备份 |

### 3.4 安全要求

| 要求 | 说明 |
|------|------|
| 认证 | 所有API端点（除登录/注册）强制JWT认证 |
| 数据隔离 | 用户间数据严格隔离，API层校验资源归属 |
| 文件安全 | 上传文件扫描，拒绝非文本类型伪装文件 |
| API Key保护 | DeepSeek API Key仅后端持有，不可泄露至前端 |
| 密码存储 | bcrypt哈希，不可逆 |

### 3.5 兼容性要求

| 端 | 支持范围 |
|------|---------|
| 浏览器 | Chrome 100+、Firefox 100+、Safari 16+、Edge 100+ |
| 分辨率 | 最小支持 1280×720，推荐 1920×1080 |
| 移动端 | v1.0仅保证基础浏览可用，不要求完整移动端适配 |

## 4. 用户场景（用例描述）

### 4.1 用例一：编剧将签约小说改编为电视剧剧本

| 字段 | 内容 |
|------|------|
| **用例编号** | UC-01 |
| **用例名称** | 长篇小说→电视剧剧本一键转换 |
| **用户角色** | 影视编剧 |
| **前置条件** | 用户已注册并登录；本地有一部12章、约20万字的小说TXT文件 |
| **优先级** | P0 |

#### 主流程

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 点击"新建项目" | 跳转至上传页面 |
| 2 | 拖拽小说TXT文件至上传区域 | 显示上传进度条，完成后展示"文件上传成功" |
| 3 | 系统自动解析章节 | 展示章节列表：共12章，每章标题+字数+序号 |
| 4 | 用户确认章节划分无误，选择"电视剧剧本"，输入集数"30" | 集数校验通过（10-60范围内），"开始转换"按钮激活 |
| 5 | 点击"开始转换" | 按钮变灰显示"转换中..."；WebSocket推送进度：第1/12章(35%)→第6/12章(60%)→第12/12章(90%)→合并中(95%)→完成(100%) |
| 6 | 转换完成后自动跳转预览页 | 展示30集电视剧剧本，每集按幕-场结构折叠展示 |
| 7 | 用户展开第1集，点击第3场进入编辑 | 进入编辑模式，可修改对白和动作描述 |
| 8 | 用户修改一处对白，点击"保存" | 前端校验Schema→通过→保存成功提示"已保存"，版本号+1 |
| 9 | 点击"导出YAML" | 浏览器下载`我的剧本_tv_series_20260605.yaml` |

#### 异常流程

| 步骤 | 异常场景 | 系统处理 |
|------|---------|---------|
| 3a | 小说只有2章，达不到3章最低要求 | 提示"小说至少需要包含3个章节，当前检测到2章"，禁止进入下一步 |
| 4a | 用户输入集数"5"（低于10） | 提示"电视剧集数范围为10-60集，请重新输入" |
| 5a | 第7章转换时LLM API超时 | 自动重试1次，仍失败→标记第7章为"失败"，其余章节继续；完成后提示"第7章转换失败，可查看详情或重新转换" |
| 5b | 用户刷新了页面 | 重新登录后，在历史项目列表找到该项目（状态：转换中），点击可继续查看进度 |
| 8a | 编辑保存时Schema校验失败 | 阻止保存，红色高亮出错字段，展示具体错误信息 |

### 4.3 用例三：制片人评估小说IP→返回历史项目二次转换

| 字段 | 内容 |
|------|------|
| **用例编号** | UC-03 |
| **用例名称** | 历史项目检索与"重新转换" |
| **用户角色** | 制片人 |
| **前置条件** | 用户一周前已将一部小说转为电影剧本（项目名称"流浪地球-电影版"），现在想用同一部小说试转电视剧 |
| **优先级** | P1 |

#### 主流程

| 步骤 | 用户操作 | 系统响应 |
|------|---------|---------|
| 1 | 登录后进入"历史项目" | 展示项目列表，分页显示，按更新时间倒序 |
| 2 | 搜索框输入"流浪"，点击搜索 | 筛选出"流浪地球-电影版"，状态为"已完成" |
| 3 | 点击该项目的"重新转换" | 弹出配置窗口：小说章节沿用原解析结果，重新选择剧本类型 |
| 4 | 选择"电视剧剧本"，输入集数"40" | 点击"开始转换" |
| 5 | 等待转换完成 | 新项目"流浪地球-电视剧版(1)"自动创建，原电影版项目不受影响 |
| 6 | 查看新生成的电视剧剧本 | 正常预览和编辑 |

#### 异常流程

| 步骤 | 异常场景 | 系统处理 |
|------|---------|---------|

## 6. 附录

### 6.1 术语表

| 术语 | 定义 |
|------|------|
| **章节** | 小说中的自然章节单位，由正则表达式识别 |
| **幕(Act)** | 剧本的一级结构单元，电影为3幕，电视剧每集通常1-2幕 |
| **场(Scene)** | 剧本的最小单元，包含单一地点+连续时间内的剧情 |
| **Hook** | 微短剧每集结尾的悬念钩子，吸引观众继续观看下一集 |
| **Schema** | 剧本YAML文件的结构规范，定义了字段名、类型、必填/可选 |
