### 1.7 导出剧本

1. 编辑完成后，点击右上角「导出」按钮。
2. 系统生成 YAML 文件并自动下载到本地。

文件命名规则：`{项目标题}_{剧本类型}_{日期}.yaml`

例如：`三体-电视剧改编_tv_series_20260605.yaml`

| 操作 | 说明 |
|------|------|

| 删除 | 删除项目及所有数据（不可恢复） |
| 重新转换 | 基于原小说重新生成（不会覆盖原项目，会生成新项目） |

### 2.2 三种剧本类型对比

| 特性 | 电影 | 电视剧 | 微短剧 |
|------|------|--------|--------|
| 适用场景 | 院线电影、网络电影 | 网剧、电视剧 | 抖音/快手竖屏短剧 |
| 输出结构 | 三幕 → 场 | 集 → 幕 → 场 | 集 → 场 |
| 场景数量 | 60-120 场 | 每集 10-15 场 | 每集 5-8 场 |
| 单集时长 | 整体 90-120 分钟 | 约 45 分钟/集 | 1-3 分钟/集 |
| 特有标记 | 无 | 集悬念钩子 | 竖屏标记 + 秒级时长 |
| 输出文件 | 单个 YAML | 单个 YAML（含全部集） | 单个 YAML（含全部集） |

### 2.3 章节管理

上传小说后，系统自动识别章节。你可以：

- **修改标题**：点击章节标题旁的编辑图标，修改章节名称。
- **合并章节**：勾选相邻两章，点击「合并」按钮。
- **拆分章节**：点击某个章节的「拆分」按钮，在弹出的文本编辑器中指定拆分点。

## 3. 剧本 YAML 结构阅读指南

了解剧本 YAML 的结构，有助于你更好地阅读和编辑剧本。

### 3.1 文件结构总览

```
剧本文件
├── schema_version    # Schema 版本号（当前 1.0）
├── meta              # 元数据（标题、作者、类型、集数等）
├── characters        # 角色列表（姓名、性格、出场等）
└── script            # 剧本正文（结构因类型而异）
    ├── [电影]        # acts → scenes
    ├── [电视剧]      # episodes → acts → scenes
    └── [微短剧]      # episodes → scenes
```

### 3.2 元数据解读

```yaml
meta:
  title: "三体-电视剧改编"     # 剧本标题
  source_novel: "三体"         # 原小说名
  author: "刘慈欣"             # 原作者
  script_type: "tv_series"     # 类型：movie/tv_series/mini_series
  total_episodes: 30           # 总集数（电视剧/微短剧特有）
  estimated_duration: 1350     # 预计总时长（分钟）
  version: 1                   # 剧本版本号
```

### 3.3 角色列表解读

```yaml
characters:
  - id: "char_001"             # 角色唯一ID（在剧本中引用）
    name: "汪淼"               # 角色姓名
    aliases: ["汪教授"]        # 别名/昵称
    gender: "male"             # 性别
    age: 35                    # 年龄
    personality_tags:          # 性格标签
      - "理性"
      - "执着"
    role: "protagonist"        # 主角/反派/配角/客串
    description: "纳米材料科学家"  # 角色简介
    first_appearance: "ep1_scene_001"  # 首次出场场次
```

### 3.4 场景内容解读

每场戏包含三种内容节点：

| 节点类型 | 标识 | 说明 |
|---------|------|------|
| `action` | 动作 | 角色的肢体动作或行为 |
| `dialogue` | 对白 | 角色说的话 |
| `description` | 描述 | 环境、氛围、镜头提示 |

```yaml
content:
  - type: "action"             # 动作节点
    text: "汪淼推开门，环顾四周。"
    subject: "char_001"        # 动作执行者（可选）

  - type: "dialogue"           # 对白节点
    character: "char_001"      # 说话角色
    text: "有人在吗？"          # 对白内容
    delivery: "试探性地"        # 表演提示（可选）
    to: "char_002"             # 对话对象（可选）

  - type: "description"        # 描述节点
    text: "房间内一片漆黑，只有月光透过窗帘的缝隙。"
    category: "atmosphere"     # 类别：环境/氛围/转场/镜头
```

### 3.5 场景信息解读

```yaml
- scene_id: "ep1_scene_001"        # 场景唯一ID
  scene_number: 1                  # 场景序号
  location: "汪淼实验室"            # 地点
  setting: "interior"              # interior=内景, exterior=外景
  time: "day"                      # day/night/dawn/dusk
  time_detail: "上午10点"          # 时间详细描述（可选）
  characters_present:              # 本场出场角色
    - "char_001"
  duration_seconds: 45             # 预估时长（微短剧特有）
  content: [...]                   # 内容节点列表
```

## 4. 常见问题

### Q1：支持什么文件格式和大小？

- **格式**：`.txt` 和 `.md`（UTF-8 编码）
- **大小**：单文件上限 50 万字（UTF-8 编码下约 1.5 MB）
- **章节要求**：至少 3 章

如果你的文件是 Word（`.docx`）或 PDF，请先转换为纯文本（`.txt`）再上传。大多数文本编辑器（记事本、VS Code）都支持「另存为」纯文本格式。

### Q2：转换需要多长时间？

| 小说规模 | 预估时间 |
|---------|---------|
| 3-5 章（约 2 万字） | 1-2 分钟 |
| 10-15 章（约 10 万字） | 3-5 分钟 |
| 30-50 章（约 30 万字） | 10-15 分钟 |
| 100 章以上（约 50 万字） | 20-30 分钟 |

转换时间受以下因素影响：
- 章节数量（每章约 15-30 秒）
- LLM 服务的繁忙程度
- 选择的模型（deepseek-chat 较快，deepseek-r1 较慢但质量更高）

### Q3：如何获得更好的剧本质量？

1. **确保小说格式规范**：章节分割清晰，使用"第X章"等标准格式。
2. **选择合适的剧本类型**：长篇小说适合电视剧，中短篇适合电影，短篇适合微短剧。
3. **使用高质量模型**：对关键章节可选择 `deepseek-r1` 模型获得更深的叙事理解。
4. **手动调整章节**：如果自动解析不准确，手动调整章节划分后再转换。
5. **善用编辑功能**：AI 生成的是初稿，请逐场检查并修改对白和动作描述。
6. **多次迭代**：对不满意的地方可以「重新转换」，基于原小说重新生成。

### Q4：转换失败了怎么办？

1. 检查项目详情页的错误信息。
2. 常见原因：
   - 文件编码不是 UTF-8 → 用记事本另存为 UTF-8 编码
   - 章节数不足 → 确保至少有 3 个章节
   - LLM 服务暂时不可用 → 等待几分钟后重试
3. 点击「重新转换」按钮重试。

### Q5：如何理解 YAML 格式的剧本？

YAML 是一种人类可读的数据格式。你可以用任何文本编辑器（记事本、VS Code、Sublime Text）打开导出的 `.yaml` 文件。推荐使用 VS Code，它自带 YAML 语法高亮，阅读更舒适。

如果你需要在其他专业软件中使用，目前仅支持 YAML 格式导出。后续版本将支持 PDF、Final Draft（FDX）等格式。

### Q6：我的数据安全吗？

- 所有上传的小说和生成的剧本仅你本人可见。
- 文件存储在加密的对象存储中。
- 密码使用 bcrypt 哈希存储，不可逆。
- LLM API 调用仅传输章节文本，不包含你的个人信息。

### Q7：如何优化微短剧的 Hook？

微短剧的 Hook（悬念钩子）是每集结尾吸引观众的关键。编辑时注意：
- Hook 应简短有力（15-30 字）。
- 制造悬念或反转，例如："他不知道，门后站着的是谁。"
- 可在编辑模式下直接修改 Hook 文案。

  -e POSTGRES_PASSWORD=novel2script \

| postgres | 5432 | 数据库 |

# 停止所有服务
docker compose down

# 查看日志

# 重启某个服务
docker compose restart celery_worker

# 水平扩展 Celery Worker（增加处理能力）
docker compose up -d --scale celery_worker=3

docker compose exec backend alembic upgrade head

如需在 Docker 中使用**开发模式**（支持热更新），使用以下命令：

```bash

```

## 附录 A：故障排查

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| 前端无法连接后端 | 后端未启动或端口被占用 | 检查 `localhost:8000` 是否可访问；检查 CORS 配置 |
| 转换任务一直不开始 | Celery Worker 未启动 | 检查 Worker 是否运行：`celery -A app.tasks.celery_app status` |
| 数据库连接失败 | PostgreSQL 未启动或配置错误 | 检查 `DATABASE_URL` 配置；确认 PostgreSQL 服务运行中 |
| LLM 调用返回错误 | API Key 无效或额度不足 | 登录 DeepSeek 平台检查 API Key 和余额 |
| 文件上传失败 | 文件过大或格式不支持 | 确保文件≤50万字且为 .txt/.md 格式 |
| Docker 端口冲突 | 宿主机端口被占用 | 修改 `docker-compose.yml` 中的端口映射 |
